## Known failures / limitations

1. **`tests/test_core.py::test_invalid_partition` — 2 failures.**
   The parametrised cases `[["a"], ["a"]]` (same report in two clusters) and `[[]]` (empty
   cluster) are expected to raise `ValueError`, but `canonicalize_partition` does not raise for
   these two inputs. The other 38 tests pass. This is an open discrepancy between the test and
   the implementation and does **not** affect the evaluation path, which validates partitions
   through `build_contingency` (strict domain equality) instead.

2. **No GPU run in this package's validation.** Threshold selection and evaluation above ran on
   CPU using the frozen Dev `.npz` caches; no DeepWide forward pass was re-executed. Re-running
   `export_pair_scores.py` on the five checkpoints is the researcher-side step that would close
   this gap.

3. **English held-out evaluation needs per-fold Gold.** `incident-align evaluate-folds --fold-gold`
   must be used for English (five disjoint Test subsets). Using a single full 5,998-case Gold
   file inflates the predicted cluster count (measured: 5,024 instead of 226 for fold_01) and
   dilutes Hungarian G→P from ≈0.57 to ≈0.63 on synthetic scores. Chinese uses a single Gold
   because all five folds score the same 1,283-report domain.

4. **The five shipped checkpoints carry legacy `prepared_dir` metadata** (old repository paths).
   `decode_graph_from_pairwise_checkpoints.py` validates that field against its config, so
   running it against the packaged layout requires retraining with the current script first.
